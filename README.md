# Описание дипломного проекта: Планировщик задач (TODO-лист)

Данный проект представляет собой веб-сервер на языке Go, реализующий функциональность планировщика задач — аналога TODO-листа. Это финальная работа, завершающая обучение по курсу Go. Проект демонстрирует навыки разработки REST API, работы с базами данных (SQLite), обработки HTTP-запросов, а также реализации сложной бизнес-логики по вычислению дат повторяющихся задач.



## Актуальность и контекст

Планировщики задач — востребованный инструмент в повседневной жизни и работе. Умение создавать такие системы требует владения широким спектром технологий: от проектирования базы данных до написания клиент-серверного взаимодействия. Данный проект объединяет все ключевые темы, изученные в курсе: основы языка Go, работа с HTTP, взаимодействие с SQLite, многопоточность (горутины), обработка JSON, а также тестирование и документирование кода.



## Цель работы

1. Разработать веб-сервер с REST API для управления задачами.
2. Реализовать поддержку периодических задач с правилами повторения (ежедневно, ежегодно).
3. Обеспечить хранение данных в SQLite с автоматическим созданием базы данных при первом запуске.
4. Предоставить удобный интерфейс через готовый фронтенд.
5. Покрыть функциональность модульными и интеграционными тестами.



## Функциональные требования

Планировщик поддерживает следующие операции:

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/api/task` | Добавление новой задачи |
| GET | `/api/tasks` | Получение списка ближайших задач (до 50) |
| GET | `/api/task?id={id}` | Получение параметров задачи по ID |
| PUT | `/api/task` | Изменение параметров задачи |
| DELETE | `/api/task?id={id}` | Удаление задачи |
| POST | `/api/task/done?id={id}` | Отметка задачи как выполненной |

### Модель задачи

Каждая задача содержит следующие поля:
- `id` — уникальный идентификатор (автоинкремент);
- `date` — дата задачи в формате `YYYYMMDD`;
- `title` — заголовок задачи (обязательное поле);
- `comment` — комментарий к задаче;
- `repeat` — правило повторения (строка, не более 128 символов).

### Правила повторения

Реализована поддержка базовых правил:
- **`d <число>`** — задача переносится на указанное число дней (максимум 400);
- **`y`** — задача выполняется ежегодно.

Если правило не указано, задача при выполнении удаляется.

### Дополнительная функциональность (со звёздочкой)

- **Поиск задач** — поддержка параметра `search` в GET-запросе `/api/tasks`:
  - поиск по подстроке в заголовке или комментарии;
  - поиск по конкретной дате (формат `DD.MM.YYYY`).

## Инструкция по запуску

### Локальный запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/kab4nsunrise/GO___FINAL___PROJECT.git
   cd GO___FINAL___PROJECT
   ```

2. **Установите зависимости:**
   ```bash
   go mod download
   ```

3. **Запустите сервер:**
   ```bash
   go run main.go
   ```

   По умолчанию сервер слушает порт `7540`. Для изменения порта установите переменную окружения:
   ```bash
   export TODO_PORT=8080
   go run main.go
   ```

4. **Откройте в браузере:** `http://localhost:7540/` (или указанный порт).

### Настройка базы данных

При первом запуске сервер автоматически создаёт файл `scheduler.db` в корневой директории и таблицу `scheduler` со следующей схемой:

```sql
CREATE TABLE scheduler (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    date CHAR(8) NOT NULL DEFAULT "",
    title VARCHAR(255) NOT NULL,
    comment TEXT,
    repeat VARCHAR(128)
);
CREATE INDEX idx_date ON scheduler(date);
```

Для указания другого пути к файлу БД используйте переменную окружения:
```bash
export TODO_DBFILE=/path/to/scheduler.db
```

## Инструкция по запуску тестов

Тесты находятся в директории `tests/` и запускаются из корня проекта:

```bash
go test ./tests
```

Для запуска конкретного теста:
```bash
go test -run ^TestAddTask$ ./tests
```

### Настройка параметров тестов

Перед запуском тестов убедитесь, что в файле `tests/settings.go` заданы корректные значения:

- `Port` — порт, на котором запущен сервер (по умолчанию `7540`);
- `DBFile` — путь к файлу базы данных (по умолчанию `../scheduler.db`);
- `FullNextDate` — установите в `true`, если реализованы все правила повторения (недели и месяцы);
- `Search` — установите в `true`, если реализован поиск задач;
- `Token` — укажите JWT-токен для тестирования аутентификации (если реализована).
